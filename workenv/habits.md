# 个人习惯画像

长期、稳定的工作方式。不是环境配置、项目状态，也不是某一张票的指令。

- 长期偏好写这里。一次性要求只写当轮的票。
- 路径和主机写 `link.md`、`env-local/`、`env-*`。
- 用过某个模型，不代表以后都用它。
- 只把状态为 **已确认** 的拿来当默认。观察中、待确认不当依据，也不拿去每轮问用户。
- 这轮用户说的永远压过旧习惯。这轮是例外就只写票；用户说以后都这样，才改本文件。
- 新环境可以几乎是空的，不填表。空着的维度保持标题即可。

单条固定：场景 / 习惯 / 默认行为 / 例外 / 来源 / 状态。不写某张票的路径和张数。

组长统一改本文件。工程师不直接改，交回里可写一行候选习惯。

## 沟通与决策

### 什么时候请人看工单

- 场景：这轮在跟用户说话
- 习惯：没点拆单就直接说怎么走，不摊工单路径
- 默认行为：没点拆任务或出工单，用人话回步骤，不编号列出 `require.md`。用户这轮点过拆单、票刚交回来，才摊路径请核对
- 例外：用户这轮自己要看某张票
- 来源：明确要求
- 状态：已确认

## 代码开发

## 数据处理

### 整理完放哪

- 场景：要把待处理里的一套收成训练 / 测试
- 习惯：待处理只留来源，结果放到旁边已经在用的正式训练目录、测试目录，名字跟着正式集
- 默认行为：不在待处理目录里另建划分结果。已有正式集不覆盖
- 例外：用户这轮指定了别的目录
- 来源：明确要求
- 状态：已确认

### 几套样本在一起时拿哪套训

- 场景：同一层里同时有误检、对照、混合
- 习惯：误检那套拿去划分；对照留在待处理；混合不当负样本
- 默认行为：按上面三套分，不把混合并进负样本，也不拿对照去训
- 例外：用户这轮点名要混着训
- 来源：明确要求
- 状态：已确认

## 模型实验

### 新版本从哪起训

- 场景：用户要一个新版本，没写接着上一版
- 习惯：用仓库训练说明里的官方初始权重从头训，不加载上一版 best
- 默认行为：开训前读该仓指导里的官方初始权重。指导没有路径就停，写进票。不拿上一版 checkpoint 续训
- 例外：用户这轮明说续训
- 来源：明确要求
- 状态：已确认

## 环境与资源

### 工程师默认用哪个模型

- 场景：组长派五名工程师子代理
- 习惯：额度紧时先用 auto，不点名 Grok
- 默认行为：各自 `.cursor/agents/` 里写 `model: auto`；派工不另指定模型。额度宽裕后再改回
- 例外：用户这轮点名某个模型
- 来源：明确要求（临时）
- 状态：已确认

## 测试与排查

### 新版本怎么测

- 场景：测一个新版本
- 习惯：同一套测试集上，上一版和新版一起出，对比有没有变好
- 默认行为：新版本测试必带上一版对照。Testdir 指标和本轮点名的 Feedback 可视化都用同一套数据。报告里并排新旧。上一版权重对不上就停，写进票。多场景要出等权场景平均（P/R/F1；变化检测再加 **mIoU**）。细则已写进 `test-engineer.md` §7
- 例外：用户这轮明说只测新版，或没有上一版
- 来源：明确要求
- 状态：已确认

## 交付与文档

### 新版本怎么归档

- 场景：训完或测完要把模型备份到本机
- 习惯：按已有那套目录拷，不另发明格式。样板是 `[ChangeDetect]-SAMCD_Building-2611-v1.4`
- 默认行为：备份根用户给，记在 `env-local/docs.md`。工程名目录里放 `checkpoint/`（`best.pth`、`checkpoint_last.pth`、events、`results.txt`、命名好的 onnx）、`config/`、`vis/`、`train.log`。训练工程师拷训练包；测试工程师把 `testlog.md` 写在该目录根上，分析报告可以后补。不把权重单独丢进算法仓 `weights/`
- 例外：用户这轮指定别的备份根或只要权重
- 来源：明确要求
- 状态：已确认

## 工作流程

### 当天任务在哪

- 场景：用户说看今天的便签、当天任务，或点名某一天
- 习惯：当天任务写在今日便签里，开口才读
- 默认行为：读地图里记下的便签目录下当天 `YYYY-MM-DD.json`。不扫盘，不改文件。没说拆任务、出工单就不拆单
- 例外：这轮给了别的日期或别的文件，听这轮的
- 来源：明确要求
- 状态：已确认
