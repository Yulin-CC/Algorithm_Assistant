# 助手初始化与用户引导

本文件是唯一一份，常驻规则里写的就是它。仓库根 `workarea/` 下不放副本，改脚本只改这里。

- **何时走**: 用户说「请进行项目初始化」或同义。其它对话不跑。
- **谁做**: 组长问和确认。写地图、探活、连服务器、建槽、装环境派运维。组长不自己装环境，不自己建槽。
- **日期**: 2026-11-24

## 1 地图

工作地图在仓库根 `workarea/`，只放这台机器的事实。连接说明只有 `workarea/link.md`。

服务本身在 `.cursor/server/`，初始化只更新其中的端口、API 和现状，不改装法。

算法仓怎么从零搭在仓库根 `buildenv/`，与机器无关，初始化不动它。

```
workarea/
├── README.md
├── env-local/
│   ├── datasets.md
│   ├── projects.md
│   └── docs.md
├── env-<主机>/
│   ├── datasets.md
│   ├── projects.md
│   └── docs.md
├── link.md
└── habits.md
```

```
buildenv/               # 施工蓝图，一仓一份，换机器不重写
├── README.md           # 索引与六节写法
└── <仓名>.md
```

```
.cursor/server/           # 服务固定这几个，初始化不改目录结构
├── README.md             # 服务总表
├── services/             # 一服务一篇：端口、模型名、注意点
├── env_building.md       # 装法。初始化不动它
├── config/               # vllm_server.json、sam.json：地址唯一权威
├── util/                 # 客户端与 probe.py
└── ledger/runs.md        # 起停台账
```

没填服务器就不建 `env-<主机>/`。文档路径可以空，`docs.md` 留占位。

## 2 步骤

1. 先向用户确认工作目录。地图全是「待确认」或空表时，直接问数据根、项目根、文档路径，不要把占位符念成这台机器的地址。已经写下具体路径时，只把这些数据根、项目根、文档路径念给用户听，请用户确认或改口。没有地图就问这三项。禁止扫全盘，禁止在确认前去列盘符。用户没给的项留空，标「待确认」。禁止猜盘，禁止沿用别的机器上没确认的地址。
2. 确认结果里涉及服务器（用户给了主机或服务器路径，或明确要连服务器）时，先做服务器初始化，再写本机地图。
    - 主机写入 `workarea/link.md`。算不算已登记，只看这一行的确认列。确认列已是「已确认」的，走 `skills/tool-remote` 做密钥探测（`BatchMode`，不索要密码）。技能表里有、确认列还是「待确认」的，先问用户是不是这台机器，再探测。新主机走该技能的 New server。探测通过也不要把确认列改成已确认，除非用户点头。用户点头后再登记进技能的 Server IDs。
    - 探测通过后，向用户确认这台机器上的数据根、项目根、服务仓库。没确认的目录不列、不扫。
    - 确认过的目录对应写进 `link.md` 和 `env-<主机>/`。
3. 只在用户确认过的目录上写地图。
    - `datasets.md` 按「到数据集」这一档展开，不写别的档。从确认过的根往下走，直到一套数据的目录。目录名属于内容层或产物层时停，不进去。内容层：`A`、`B`、`images`、`json`、`jsons`、`jsons-*`、`label`、`labels`、`labels-*`、`annotations`。产物层：`repro`、`draft`、`cache`、`__pycache__`、`crop`、`vis`、`vis-*`、`bcd_map`、`vismask`、`register`、`register_B`。停住的目录写在父级同一行，附这个目录直接文件的扩展名和数量。不写单个文件名。
    - `projects.md` 只到仓库一层：仓库名加一句它是什么。不套用上面的内容层、产物层停名，不进源码、权重、`.git`。
    - 只读已经确认的根。用户明确说先别展开时，数据根只留直接子目录，并注明还没按「到数据集」展开。项目根仍只到仓库一层。
4. 派运维在 `.cursor` 下跑 `python server/util/probe.py`。按条登记到 `server/README.md` 第 1 节和对应 `server/services/*.md` 的「现状」。有地址但探活失败，状态写「未跑」，不要问有没有地址。没有地址才问；用户也没有，就留占位。两种情况都写明缺了会影响识图、预标、补标里的哪一块。整次探活失败只说明默认模型或 SAM 不通；其它通的按条登记，不把 FP8 改成默认。Windows 不起 vLLM / SAM。现在搭不搭留到第 7 步。
5. 服务固定是 Qwen、GroundingPI、Triton SAM 这几个，`server/env_building.md` 里已写好装法，初始化**不改它**。要补的是这台机器的事实：`workarea/link.md` 记启动脚本绝对路径与权重目录；`server/services/*.md` 的「现状」写这台机器上能不能起。到服务器上找对应仓库的 `README.md` 核对装法，与本文件不符的写进 `env_building.md` §3「已知坑」并注明摘自哪份 README。写明登录用户、conda 根、权重根、数据根；这四项可以不在同一个 home。脚本在、权重目录不在的，在 `link.md` 标明「现在不能起」。找不到 README 就写明缺的是哪一条路径，不要留成空话。真正安装仍派运维，初始化本身不启动服务。
6. 请用户看 `workarea/README.md` 和 `server/README.md` 并确认。用户看过并点头之前，确认列不能改成已确认，也不把这张地图当成新机器的默认。点头之后，把探到的地址写回 `server/config/vllm_server.json` 和 `sam.json`。用户后来改了 `workarea/link.md` 的路径，同步 `env-*/`；改了服务地址或端口，先写回两个 json，再干活。
7. 再问一轮，两句一起问。用户说先不做就停，直接说第 3 节的开场白。
    - 要看哪个项目仓。只看点名的那一个，不扫 `projects.md` 里的全部仓库。两选一：按 `skills/standard-project_merge` 整理（改动大，先说清楚再动），或只按 `skills/standard-project_agentdemo` 建 `0-Agent-demo`（可删）。整理和建槽派运维，不开训。
    - 缺的服务现在搭不搭。要搭先看组长房间：同一 GPU 或端口已有人在用，先说明，不搭。没有占用再看 GPU，按 `server/env_building.md` 派运维。权重目录不存在的服务不排进「现在能起」。启动脚本以 `link.md` 为准。

## 3 开场白

确认完（即使用户跳过第 7 步）由组长说：

嗨！初次见面，我是你的算法助手！地图已经铺好啦。数据、训练、测试、环境，你指到哪儿，我就干到哪儿。缺的服务我记在 .cursor/server/ledger/runs.md 了，想搭的时候喊我一声，马上安排！
